## 들어가며

[Docker란 무엇일까?](/infra/2024/03/15/Docker.html) 글에서 도커가 왜 나왔는지를 정리했습니다. 이번에는 Docker 강의를 들으면서 정리한 내용 중, 도커를 쓰려면 꼭 알아야 하는 **이미지**와 **컨테이너**의 개념을 정리해 보겠습니다.

> 도커는 애플리케이션을 **어디서든지 같은 환경으로** 실행하게 해주는 도구입니다.

설치가 잘 되었는지는 아래 두 명령어로 확인할 수 있습니다.

```bash
docker run hello-world   # 테스트용 이미지로 컨테이너를 실행
docker ps                # 실행 중인 컨테이너 목록
```

## 1. 이미지 (Image)

> 이미지는 애플리케이션을 실행하는 데 필요한 **모든 것을 담고 있는 패키지**입니다.

이미지의 가장 중요한 특징은 **읽기 전용**이라는 점입니다.

* 한 번 만들어진 이미지는 내용이 바뀌지 않습니다.
* 내용을 바꾸고 싶다면 이미지를 고치는 게 아니라, **새로운 이미지**를 받거나 새로 만들어야 합니다.

## 2. 컨테이너 (Container)

> 컨테이너는 **이미지를 기반으로 실행되는 인스턴스**입니다.

이미지가 설계도라면 컨테이너는 그 설계도로 실제로 띄운 실행 단위라고 생각하면 됩니다. 하나의 이미지로 여러 개의 컨테이너를 만들 수 있고, 각 컨테이너는 **서로 독립적으로** 돌아갑니다.

### 쓰기 레이어

이미지는 읽기 전용인데, 컨테이너 안에서 파일을 만들거나 고치면 어떻게 될까요?

컨테이너를 실행하면 이미지 위에 **쓰기 레이어(Writable Layer)**가 하나 추가됩니다.

* 컨테이너 안에서 무언가를 수정하면, 그 변경 사항은 **쓰기 레이어에만** 기록됩니다.
* 아래에 있는 이미지는 읽기 전용이라 아무것도 바뀌지 않습니다.

그래서 하나의 이미지로 컨테이너를 여러 개 만들어도 서로 **간섭이 없습니다**. 각자 자기만의 쓰기 레이어를 가지기 때문입니다.

## 3. 레이어 구조 (Union File System)

이미지는 한 덩어리가 아니라 **여러 개의 레이어가 쌓인 구조**입니다. 이렇게 여러 레이어를 겹쳐서 하나의 파일 시스템처럼 보여주는 방식을 **유니온 파일 시스템(Union File System)**이라고 합니다.

예를 들어 Nginx 웹 서버 이미지는 다음과 같이 쌓일 수 있습니다.

| 레이어 | 내용 |
| --- | --- |
| 레이어 4 | 기본 HTML 파일 복사 |
| 레이어 3 | 설정 파일 복사 |
| 레이어 2 | Nginx 설치 |
| 레이어 1 | Base OS |

컨테이너를 실행하면 이 위에 앞에서 말한 쓰기 레이어가 한 장 더 올라갑니다.

### 왜 레이어로 나눴을까?

이유는 **효율성** 때문입니다.

* 모든 이미지 레이어는 **읽기 전용**이라, 같은 레이어를 여러 이미지와 컨테이너가 함께 써도 안전합니다.
* 이미 받아 둔 레이어는 다시 받지 않고 재사용합니다. 실제로 `docker pull`을 해 보면 일부 레이어가 `Already exists`로 표시되는 것을 볼 수 있습니다. (다음 글에서 확인합니다.)

## 4. 컨테이너 생명주기

컨테이너는 다음과 같은 상태를 거칩니다.

| 상태 | 의미 |
| --- | --- |
| Created | 생성됨 (아직 실행 전) |
| Running | 실행 중 |
| Paused | 일시정지 |
| Stopped | 중지됨 (`docker ps -a`에서는 `Exited`로 표시) |
| Deleted | 삭제됨 |

삭제된 컨테이너는 **복구할 수 없습니다**. 컨테이너 안에서 바꾼 내용은 그 컨테이너의 쓰기 레이어에만 있었기 때문에, 컨테이너를 지우면 함께 사라집니다.

## 5. 도커는 어떻게 가벼울 수 있을까?

컨테이너는 가상 머신처럼 운영체제 전체를 따로 띄우지 않습니다. 리눅스 컨테이너는 **호스트의 리눅스 커널을 함께 쓰면서** 프로세스와 파일 시스템만 격리해서 실행합니다. 그래서 가볍고 빠르게 뜨고, 각 컨테이너는 독립적으로 돌아갑니다.

참고로 macOS나 Windows에는 리눅스 커널이 없기 때문에, Docker Desktop은 내부적으로 **경량 리눅스 가상 머신**을 하나 띄우고 그 위에서 컨테이너를 실행합니다.

## 정리

* **이미지**: 애플리케이션 실행에 필요한 모든 것을 담은 **읽기 전용** 패키지
* **컨테이너**: 이미지를 기반으로 실행되는 인스턴스. 실행 시 **쓰기 레이어**가 추가되고, 변경 사항은 여기에만 기록됨
* 이미지는 여러 **레이어**가 쌓인 구조(유니온 파일 시스템)이고, 레이어를 재사용해서 효율적임
* 하나의 이미지로 여러 컨테이너를 만들어도 서로 간섭하지 않음
* 컨테이너 생명주기: Created → Running ⇄ Paused → Stopped → Deleted (삭제하면 복구 불가)
