## 들어가며

[이미지 다루기](/docker/2026/11/24/Docker-이미지-받기와-정리.html) 글에서 이미지를 받고 정리하는 방법을 정리했습니다. 이번 글에서는 이미지로 **컨테이너를 실행하고, 멈추고, 로그를 보고, 안에 들어가 보는** 명령어를 실습한 내용을 정리합니다.

## 1. 컨테이너 실행하기 - docker run

`docker run`은 이미지로 **새 컨테이너를 만들고 실행**하는 명령어입니다. (이미지가 없으면 먼저 받아옵니다.) 실행 방식은 크게 두 가지입니다.

### 포그라운드 실행 (-it)

```bash
docker run -it ubuntu
```

* `-i` (interactive): 컨테이너의 표준 입력(STDIN)을 열어 두어 **입력을 보낼 수 있게** 합니다.
* `-t` (tty): 가상 터미널을 할당해서 **터미널처럼 쓸 수 있게** 합니다.

두 옵션을 함께 쓰면 우분투 컨테이너가 실행되면서 그 안의 쉘에 **바로 접속**됩니다.

### 백그라운드 실행 (-d)

```bash
docker run -d nginx
```

* `-d` (detached): 컨테이너를 백그라운드에서 실행하고 **터미널 제어권이 나한테 바로 돌아옵니다.**
* 웹 서버나 데이터베이스처럼 **계속 떠 있어야 하는 것**을 실행할 때 사용합니다.

```bash
docker ps
```

`STATUS`가 `Up ...`이면 실행 중이라는 뜻입니다.

| 방식 | 옵션 | 특징 | 용도 |
| --- | --- | --- | --- |
| 포그라운드 | `-it` | 컨테이너에 바로 접속 | 쉘로 들어가서 작업할 때 |
| 백그라운드 | `-d` | 터미널 제어권을 뺏기지 않음 | 서버, 데이터베이스 |

### 컨테이너 이름 붙이기 (--name)

```bash
docker run -d --name my-nginx nginx
```

이름을 붙이면 이후 명령어에서 긴 컨테이너 ID 대신 이름(`my-nginx`)으로 컨테이너를 가리킬 수 있습니다.

```bash
% docker run -d --name web1 nginx
71e181db4878fc6d07afe1fa618dcfa8d649a88083acd2b4d8a2d23fd532b194

% docker run -d --name web nginx
3171b351fe6c5becca60441702e40bf593c59500c470b83294345eede412ad00

% docker run -d --name web2 nginx
cf4b55517700489e7646a7e12ce6063f9b2a25fb377e71bc8b118b7984056c43

% docker run --name test1 ubuntu echo "done"
```

`-d`로 실행하면 만들어진 컨테이너의 ID가 출력되고 바로 프롬프트가 돌아옵니다. 하나의 `nginx` 이미지로 컨테이너 3개를 띄운 것인데, 각 컨테이너는 서로 독립적으로 돌아갑니다.

마지막 `test1`은 `echo "done"`을 실행하고 **바로 종료**됩니다. 컨테이너는 **메인 프로세스가 살아 있는 동안만** 실행되기 때문입니다.

### nginx 컨테이너는 왜 안 꺼질까?

`docker ps`로 nginx 컨테이너를 보면 `COMMAND`에 이런 값이 보입니다.

```
"/docker-entrypoint.sh nginx -g 'daemon off;'"
```

* `/docker-entrypoint.sh`: 컨테이너가 시작될 때 실행되는 준비 스크립트입니다. 준비 작업을 마친 뒤 뒤에 오는 명령어(`nginx ...`)를 실행합니다.
* `nginx -g 'daemon off;'`: nginx를 **데몬(백그라운드)으로 돌리지 말고 포그라운드로 실행**하라는 설정입니다.

nginx가 스스로 백그라운드로 빠져 버리면 메인 프로세스가 끝난 것으로 보고 컨테이너도 종료됩니다. 그래서 `daemon off`로 nginx를 메인 프로세스로 붙잡아 두는 것입니다.

## 2. 컨테이너 멈추고 지우기

```bash
docker stop web1          # 정상 종료 요청, 기본 10초 기다린 뒤 강제 종료
docker stop -t 5 web2     # 5초만 기다림
docker restart web1       # 재시작
docker rm -f web2         # 실행 중이어도 강제로 종료하고 삭제
```

`docker stop`은 먼저 컨테이너에 종료 신호(SIGTERM)를 보내고, 기본 **10초 정도 기다렸다가** 그래도 안 꺼지면 강제로 종료(SIGKILL)합니다. `-t`로 기다리는 시간을 바꿀 수 있습니다.

`docker rm -f`는 기다리지 않고 바로 강제 종료하기 때문에, 애플리케이션이 정리 작업을 할 기회가 없습니다. 그래서 **`stop`으로 멈춘 뒤 `rm`으로 지우는 것을 추천**합니다.

### 한 번에 정리하기

```bash
docker ps -q                    # 실행 중인 컨테이너의 ID만 출력
docker stop $(docker ps -q)     # 실행 중인 컨테이너 전부 중지
docker stop $(docker ps -q) && docker container prune -f  # 전부 중지 후, 중지된 컨테이너 전부 삭제
```

`$(...)`는 괄호 안 명령어의 결과를 인자로 넘겨줍니다. 그래서 `docker ps -q`로 나온 ID들이 전부 `docker stop`에 전달됩니다. (중지된 컨테이너까지 포함한 전체 ID는 `docker ps -aq`)

두 명령어는 `&&`로 이어야 합니다. `&&`는 앞 명령어가 성공하면 뒤 명령어를 실행하지만, `&` 하나만 쓰면 앞 명령어를 백그라운드로 보내고 뒤 명령어를 **동시에** 실행해서, 아직 멈추지 않은 컨테이너는 삭제되지 않을 수 있습니다.

## 3. 로그 보기 - docker logs

```bash
docker logs -f log-test           # 로그를 실시간으로 계속 출력 (follow)
docker logs --tail 5 log-test     # 마지막 5줄만 출력
docker logs -t log-test           # 시간값(타임스탬프)도 함께 출력
docker logs --since 10m log-test  # 최근 10분 동안의 로그만 출력
```

## 4. 실행 중인 컨테이너에서 명령어 실행 - docker exec

`docker exec`는 **이미 실행 중인 컨테이너** 안에서 명령어를 실행합니다.

```bash
docker exec my-nginx cat /etc/nginx/nginx.conf   # nginx 설정 파일 출력
docker exec my-nginx ls /usr/share/nginx/html    # 기본 HTML 폴더 확인
docker exec my-nginx env                         # 환경 변수 확인
docker exec my-nginx hostname -i                 # 컨테이너 IP 확인
```

### run -it vs exec -it

둘 다 컨테이너 안의 쉘에 들어갈 수 있지만, 동작이 다릅니다.

| | `docker run -it` | `docker exec -it` |
| --- | --- | --- |
| 컨테이너 | **새 컨테이너** 생성 | **기존 컨테이너**에 접속 |
| 쉘 | 쉘이 **메인 프로세스** | 쉘은 **추가 프로세스** |
| `exit` 하면 | 컨테이너 **종료** | 컨테이너는 **유지** |

앞에서 본 것처럼 컨테이너는 메인 프로세스가 끝나면 종료되기 때문에 이런 차이가 생깁니다. 실행 중인 서버 컨테이너를 들여다볼 때는 `exec -it`를 써야 서버가 꺼지지 않습니다.

## 5. 파일 복사하기 - docker cp

`docker cp`로 내 컴퓨터(호스트)와 컨테이너 사이에 파일을 복사할 수 있습니다.

```bash
docker cp [호스트 경로] [컨테이너]:[컨테이너 경로]   # 호스트 → 컨테이너
docker cp [컨테이너]:[컨테이너 경로] [호스트 경로]   # 컨테이너 → 호스트
```

### 호스트 → 컨테이너: nginx 기본 페이지 바꾸기

```bash
% echo '<h1> Hello from Docker!</h1>' > /tmp/index.html
% docker cp /tmp/index.html my-nginx:/usr/share/nginx/html/index.html
Successfully copied 29B (transferred 2.05kB) to my-nginx:/usr/share/nginx/html/index.html
% docker exec my-nginx cat /usr/share/nginx/html/index.html
<h1> Hello from Docker!</h1>
```

만든 HTML 파일을 nginx의 기본 페이지 위치에 덮어쓰고, `docker exec`로 바뀐 것을 확인했습니다.

### 컨테이너 → 호스트: nginx 설정 파일 꺼내기

```bash
% docker cp my-nginx:/etc/nginx/nginx.conf /temp/nginx.conf
invalid output path: directory "/temp" does not exist
% docker cp my-nginx:/etc/nginx/nginx.conf /tmp/nginx.conf
Successfully copied 644B (transferred 2.56kB) to /tmp/nginx.conf
% cat /tmp/nginx.conf

user  nginx;
worker_processes  auto;
...
http {
    include       /etc/nginx/mime.types;
    ...
    include /etc/nginx/conf.d/*.conf;
}
```

처음에는 `/tmp`를 `/temp`로 잘못 적어서 실패했습니다. 복사할 호스트 쪽 **폴더가 실제로 있어야** 합니다.

## 정리

| 명령어 | 설명 |
| --- | --- |
| `docker run -it ubuntu` | 새 컨테이너를 만들고 쉘에 바로 접속 (포그라운드) |
| `docker run -d --name my-nginx nginx` | 이름을 붙여 백그라운드로 실행 |
| `docker ps` / `docker ps -q` | 실행 중인 컨테이너 목록 / ID만 |
| `docker stop -t 5 web2` | 정상 종료 요청 (기본 10초 뒤 강제 종료) |
| `docker restart web1` | 재시작 |
| `docker rm -f web2` | 강제 종료 후 삭제 (`stop` → `rm` 추천) |
| `docker container prune -f` | 중지된 컨테이너 전부 삭제 |
| `docker logs -f / --tail / -t / --since` | 로그 보기 |
| `docker exec my-nginx [명령어]` | 실행 중인 컨테이너에서 명령어 실행 |
| `docker cp` | 호스트 ↔ 컨테이너 파일 복사 |

* 컨테이너는 **메인 프로세스가 살아 있는 동안만** 실행됨
* 서버·DB는 `-d`로 백그라운드 실행
* 실행 중인 컨테이너를 들여다볼 때는 `run -it`가 아니라 `exec -it`
