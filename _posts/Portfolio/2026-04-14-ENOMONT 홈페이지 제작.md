한의학 기반의 생체 신호 분석 기술을 연구하는 기업 ENOMONT의 공식 홈페이지를 개발한 프로젝트입니다. 기업의 기술력과 전문성을 효과적으로 전달하기 위해 애니메이션 시각화와 반응형 웹 디자인을 적용했으며, 클라이언트에게 직관적이고 신뢰감 있는 UI/UX를 제공하는 데 중점을 두었습니다. 이후 바이오센서(EN-100)로 측정한 환자 데이터를 웹에서 확인할 수 있는 **측정 결과서 페이지**까지 함께 개발했습니다.

서비스 Url : [ENOMONT 홈페이지 바로 가기](https://enomont.com)

![썸네일](/assets/images/posts/thumbnail.png)

## 1. 프로젝트 개요
* 성격: 기업 공식 홈페이지 외주 제작
* 기간: 2026.04 - 2026.04
* 규모: 1인 개발 (단독 수행)

## 2. 기술 스택
* Library: React, React Router, styled-components, Axios, ApexCharts, Spring Boot
* Build: Vite
* Language: JavaScript, HTML5, CSS3, Java

## 3. 주요 기술적 성과

<img src="/assets/images/posts/enomont-home-hero.png" alt="ENOMONT 홈페이지 메인 화면">

### 컴포넌트 기반 아키텍처 및 모듈화
* 효율적인 코드 관리를 위해 React의 컴포넌트 구조를 도입했습니다. 히어로, 연혁, 소프트웨어 섹션을 각각 독립된 컴포넌트로 분리하고, 라우트는 메인 페이지와 측정 결과서 페이지 두 개로 구성했습니다.
* 스타일은 styled-components로 컴포넌트와 함께 관리했습니다. 브랜드 색상은 CSS 변수로 모아 두어 색이 바뀌어도 한 곳만 고치면 되도록 했습니다.
* 여러 섹션에서 쓰이는 버튼은 종류를 상수로 정의하고, 종류만 넘기면 알맞은 스타일의 버튼이 렌더링되도록 하나의 공통 컴포넌트로 묶었습니다.
* 제목의 그라데이션 글씨도 시작 색, 끝 색, 크기를 props로 받는 컴포넌트로 만들어 히어로와 각 섹션 제목에서 재사용했습니다.

### 반응형 웹 디자인 구현
<img src="/assets/images/posts/enomont-home-mobile.png" alt="모바일 화면" style="max-width: 320px">

* 다양한 기기 환경(PC, 태블릿, 모바일)에 대응하기 위해 반응형 웹으로 구축했습니다. 태블릿과 모바일 두 개의 브레이크포인트를 기준으로 레이아웃이 자연스럽게 재배치되도록 구현했습니다.
* 인증서 목록은 CSS Grid로 PC에서는 4열, 모바일에서는 2열로 바뀝니다.
* 히어로 제목은 화면 너비에 비례해 커지고 줄어들도록 해서, 브레이크포인트마다 글자 크기를 따로 지정하지 않아도 되도록 했습니다. 한글이 단어 중간에서 어색하게 끊기지 않도록 단어 단위 줄바꿈도 함께 적용했습니다.

### 인터랙티브 애니메이션 시각화
* 정적인 기업 정보에 동적인 요소를 부여하여 사용자 경험을 향상시켰습니다.
* **패럴랙스 스크롤**: 스크롤 위치에 따라 히어로 배경을 콘텐츠보다 느린 속도로 움직여, 배경과 콘텐츠 사이에 깊이감이 느껴지도록 했습니다.
* **맨 위로 버튼**: 페이지를 일정 이상 내려가면 버튼이 나타나고, 누르면 부드러운 스크롤로 맨 위로 돌아갑니다.
* **배경 도형과 버튼 애니메이션**: 히어로 배경의 도형은 비대칭 곡선으로 유기적인 모양을 만들고 천천히 떠다니게 했습니다. 다운로드 버튼은 그라데이션 색이 흐르는 효과를 줬고, Hover 시 살짝 떠오르도록 했습니다.

### 소프트웨어 이미지 자동 슬라이더
<img src="/assets/images/posts/enomont-home-software.png" alt="EN-100 소프트웨어 슬라이더">

* EN-100 전용 소프트웨어 화면은 일정 시간마다 자동으로 넘어가는 슬라이더로 보여주고, 마지막 이미지 다음에는 다시 첫 이미지로 돌아갑니다.
* 사용자가 이미지를 보는 중에 넘어가지 않도록 마우스를 올리면 자동 전환을 멈춥니다. 멈춤 상태는 리렌더링 없이 타이머에서 항상 최신 값을 읽을 수 있도록 ref로 관리했습니다.
* 이전/다음 버튼을 누르면 타이머를 초기화해서, 수동으로 넘긴 직후 곧바로 자동 전환이 일어나지 않도록 했습니다.

### 이미지 확대 모달
<img src="/assets/images/posts/enomont-home-lightbox.png" alt="인증서 확대 모달">

* 연혁 섹션의 인증서와 하드웨어 이미지를 누르면 원본 비율 그대로 크게 볼 수 있는 모달을 띄웁니다.
* 모달이 열려 있는 동안 뒤쪽 페이지가 스크롤되지 않도록 막았습니다. 이때 스크롤바가 사라지면서 페이지가 옆으로 밀리는 문제가 있어, 스크롤바 너비만큼 여백을 채워 레이아웃이 흔들리지 않도록 했습니다.
* 닫을 때는 바로 사라지지 않고 닫힘 애니메이션이 끝난 뒤에 제거되도록 했습니다.

<img src="/assets/images/posts/enomont-home-history.png" alt="회사 연혁 섹션">

* 연혁과 인증서 목록은 마크업에 직접 쓰지 않고 데이터 배열로 분리해 렌더링해서, 연혁이 추가되어도 데이터만 수정하면 되도록 했습니다.

## 4. 바이오센서 측정 결과서 페이지

서비스 Url : [측정 결과서 예시 바로 가기](https://enomont.com/view/i7qwTvL%2BCpM1xsKDVU59QA%3D%3D/0TRruBNqqv4x%2F3xS2gLo7mnN0WdB3zFdKrX5AqNBAKo%3D)

바이오센서 EN-100으로 측정한 결과를 환자가 링크 하나로 확인할 수 있도록 만든 결과서 페이지입니다. 상단에 환자 정보와 측정일, 인체 이미지 위에 표시되는 부위별 상태, 하단에 영역별 측정 수치 차트가 이어지는 구조입니다. 결과서는 주로 휴대폰으로 열어보기 때문에 모바일 화면을 기준으로 설계했습니다.

<img src="/assets/images/posts/enomont-report-full.png" alt="측정 결과서 전체 화면" style="max-width: 400px">

> 스크린샷의 환자 개인정보(이름, 성별, 측정일)는 모자이크 처리했습니다.

### Tenant 서버를 활용한 데이터베이스 스와핑
측정 데이터는 측정을 진행한 기관(Tenant)마다 별도의 데이터베이스에 저장됩니다. 결과서 페이지 하나로 모든 기관의 데이터를 보여주기 위해, 요청마다 조회할 DB를 바꿔 주는 동적 라우팅 구조를 만들었습니다.

* **DB 이름만 교체**: 기본 DB 설정을 기준으로 접속 정보는 그대로 두고 DB 이름만 바꿔 연결합니다. 그래서 기관이 새로 추가되어도 설정을 고칠 필요가 없습니다.
* **커넥션 풀 재사용**: 요청마다 커넥션 풀을 새로 만들면 비용이 크기 때문에, 한 번 만든 DB별 풀은 등록해 두고 재사용합니다. 기관 수만큼 풀이 늘어나는 구조이므로 풀당 최대 커넥션 수를 작게 제한했습니다.
* **요청 단위 컨텍스트 관리**: 조회할 DB 정보는 요청을 처리하는 스레드에만 보관하고, 쿼리가 실행될 때 그 정보를 보고 알맞은 DB로 보냅니다. 서버는 스레드를 재사용하기 때문에, 요청이 끝날 때마다 이 정보를 반드시 비워 다음 요청이 다른 기관의 DB를 조회하는 일이 없도록 했습니다.

### 비트맵 기반 인체 상태 시각화
<img src="/assets/images/posts/enomont-report-body.png" alt="인체 부위별 상태 시각화" style="max-width: 400px">

* 측정값을 매우 높음, 높음, 보통, 낮음, 매우 낮음의 5단계로 나누고, 단계마다 빨강·주황·노랑·초록·파랑 색을 지정했습니다.
* 기본 인체 이미지 위에 머리, 가슴, 복부, 하지 등 부위별 비트맵 이미지를 색상 단계별로 미리 준비해 두고, 각 부위의 측정값에 해당하는 색상의 이미지를 골라 겹쳐 그리는 방식으로 구현했습니다.
* 부위별 레이어의 가장자리를 부드럽게 처리해서, 수치를 하나하나 읽지 않아도 히트맵처럼 어느 부위의 상태가 좋지 않은지 한눈에 들어오도록 했습니다.

### ApexCharts를 활용한 측정 데이터 시각화
<img src="/assets/images/posts/enomont-report-filter.png" alt="영역별 측정 데이터 차트" style="max-width: 400px">

* 머리, 호르몬, 자율신경, 소화기 등 12개 영역의 세부 측정값을 ApexCharts의 가로 막대 차트로 보여줍니다. 예를 들어 소화기 영역에서는 위, 십이지장, 소장, 대장 등 장기별 수치를 한 차트에서 비교할 수 있습니다.
* 영역마다 소견(예: 소화장애, 배변장애)을 차트 위에 함께 표시해서, 수치와 그 의미를 같이 볼 수 있게 했습니다.
* 측정 데이터 요청은 커스텀 훅으로 분리했습니다. 훅이 요청과 함께 로딩·에러 상태를 관리하기 때문에, 화면 컴포넌트는 상태에 따라 알맞은 화면을 그리기만 하면 됩니다.
* 상단의 영역 필터 버튼으로 전체 영역을 보거나 원하는 영역만 골라 볼 수 있습니다. 차트 12개를 같은 옵션 구조로 만들고 데이터만 바꿔 넣도록 구성해서 영역이 늘어나도 쉽게 추가할 수 있습니다.

## 5. 학습 및 성찰

### UI/UX 디자인의 중요성 체감
* 단순히 기능을 구현하는 것을 넘어, 기업의 아이덴티티와 전문성을 시각적으로 어떻게 표현할지에 대한 깊은 고민을 했습니다. 사용자 동선과 정보 계층을 고려한 UI/UX 설계가 웹사이트의 가치를 결정짓는 핵심 요소임을 깨달았습니다.

### 반응형 레이아웃 설계에 대한 고찰
* 반응형 웹을 개발하며 단순히 화면 크기를 줄이는 것이 아니라, 기기별로 최적화된 정보 배치와 UI 요소의 변화를 어떻게 설계해야 하는지 깊이 있게 고민하고 적용해 볼 수 있었습니다.

### 인프라 및 보안 개념 확립
* 프로젝트를 배포하는 과정에서 SSL 인증서 발급 및 적용을 통해 웹 보안의 기초를 다졌으며, Nginx 등을 활용한 리버스 프록시(Reverse Proxy) 개념을 학습하고 실무에 적용해 보며 백엔드 인프라에 대한 이해도를 넓혔습니다.

### 의료 데이터를 다루는 화면에 대한 고민
* 측정 결과서를 만들며 같은 데이터라도 숫자로 보여줄 때와 색상·이미지로 보여줄 때 전달력이 크게 다르다는 것을 느꼈습니다. 전문 지식이 없는 환자도 이해할 수 있도록 인체 이미지로 먼저 전체 상태를 보여주고, 자세한 수치는 차트로 확인하게 하는 순서로 화면을 구성했습니다.
* 또한 기관별로 데이터베이스를 분리하는 Tenant 구조를 다뤄 보면서, 요청이 끝난 뒤 컨텍스트를 비우는 것처럼 작은 처리 하나를 놓치는 것이 다른 기관의 데이터를 노출하는 문제로 이어질 수 있다는 것을 알게 됐습니다. 민감한 데이터를 다룰수록 데이터를 어떻게 나누고 요청 단위로 격리할지 미리 설계해야 한다는 것을 배웠습니다.
