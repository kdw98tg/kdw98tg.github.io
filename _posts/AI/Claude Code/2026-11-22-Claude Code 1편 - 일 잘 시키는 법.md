## 들어가며

Claude Code를 처음 쓰면 보통 "이거 고쳐줘", "저거 만들어줘"처럼 짧게 요청하게 됩니다. 간단한 일은 그래도 잘 되지만, 조금만 복잡해지면 엉뚱한 곳을 고치거나 부탁하지 않은 기능까지 잔뜩 만들어 오는 경우가 생깁니다.

Claude가 일을 못해서라기보다는, **무엇을 어디까지 해야 하는지 모르기 때문**인 경우가 대부분입니다. 이번 글에서는 일부러 버그를 심어둔 Unity 스크립트를 가지고, 같은 버그를 "대충 시킬 때"와 "제대로 시킬 때" 결과가 어떻게 달라지는지 직접 비교해 보겠습니다.

> 이 글은 Claude Code 실전 활용 시리즈의 1편입니다. Claude Code 설치와 Unity MCP 연결은 이미 끝났다고 가정합니다. MCP 연결은 [Unity MCP 서버 연결하기](/game%20engine/2026/10/20/Unity-Mcp-%EC%84%9C%EB%B2%84-%EC%97%B0%EA%B2%B0.html) 글을 참고해 주세요.

이번 글에서 다룰 내용은 다음과 같습니다.

* 탐색 → 계획 → 구현 → 검증으로 이어지는 기본 흐름
* Plan mode로 계획부터 승인받기
* 좋은 프롬프트를 쓰는 요령
* 권한 모드와 되돌리기(`/rewind`)

## 1. 실습 준비 - 버그가 있는 스크립트 만들기

먼저 실습에 쓸 씬을 만들어 줍니다.

1. `Hierarchy`에서 `3D Object > Plane`을 만들고 이름을 `Ground`로 바꿉니다.
2. `3D Object > Capsule`을 만들고 이름을 `Player`로 바꾼 뒤, Position Y를 `1`로 올립니다.
3. `Player`에 `Rigidbody` 컴포넌트를 추가합니다. 넘어지지 않도록 `Constraints > Freeze Rotation`의 X, Z를 체크합니다.

<!-- 📷 스크린샷: Ground와 Player가 배치된 씬, Rigidbody 설정 -->

다음으로 `Assets/Scripts/PlayerController.cs`를 만들고 아래 코드를 그대로 붙여넣은 뒤 `Player`에 붙여줍니다.

```csharp
using UnityEngine;
using UnityEngine.InputSystem;

public class PlayerController : MonoBehaviour
{
    public float moveSpeed = 5f;
    public float jumpForce = 5f;
    Rigidbody rb;

    void Start() { rb = GetComponent<Rigidbody>(); }

    void Update()
    {
        var kb = Keyboard.current;
        float h = (kb.dKey.isPressed ? 1 : 0) - (kb.aKey.isPressed ? 1 : 0);
        float v = (kb.wKey.isPressed ? 1 : 0) - (kb.sKey.isPressed ? 1 : 0);
        transform.Translate(new Vector3(h, 0, v) * moveSpeed * Time.deltaTime);

        if (kb.spaceKey.wasPressedThisFrame)
            rb.AddForce(Vector3.up * jumpForce, ForceMode.Impulse);
    }
}
```

> Unity 6의 새 프로젝트는 기본값이 **새 Input System**입니다. 예전처럼 `Input.GetAxis`를 쓰면 Play 모드에서 바로 에러가 나기 때문에, 위 코드는 `Keyboard.current`를 사용했습니다.

이 코드에는 일부러 버그를 두 개 심어두었습니다.

1. **공중에서도 계속 점프가 됩니다.** 땅에 닿아 있는지 확인하지 않고 스페이스바를 누를 때마다 힘을 주기 때문입니다.
2. **Rigidbody가 있는데 `transform.Translate`로 움직입니다.** 물리 엔진을 무시하고 위치를 직접 옮기기 때문에, 벽을 뚫거나 덜덜 떨리는 문제가 생길 수 있습니다.

Play 모드에서 WASD로 움직이고 스페이스바를 연타해서, 하늘로 계속 올라가는 것을 확인해 둡니다.

## 2. 기본 흐름 - 탐색 → 계획 → 구현 → 검증

Claude에게 일을 맡길 때는 아래 네 단계를 기억하면 좋습니다.

| 단계 | 하는 일 | 예시 프롬프트 |
|---|---|---|
| 탐색 | 관련 코드를 읽고 현재 상태 파악 | "PlayerController.cs를 읽고 구조를 설명해줘" |
| 계획 | 무엇을 어떻게 바꿀지 정리 | "고치기 전에 계획만 먼저 보여줘" |
| 구현 | 승인한 계획대로 수정 | "좋아, 그대로 진행해줘" |
| 검증 | 제대로 고쳐졌는지 확인 | "어떻게 확인하면 되는지 알려줘" |

사람에게 일을 맡길 때와 똑같습니다. 신입 개발자에게 "점프 고쳐"라고만 하면 어디를 어떻게 고칠지 혼자 추측해야 합니다. 상황을 설명하고, 계획을 들어보고, 결과를 확인하는 과정이 있어야 원하는 결과가 나옵니다.

## 3. 실습 1 - 대충 시켜보기

먼저 일부러 대충 요청해 보겠습니다.

```
점프 고쳐줘
```

<!-- 📷 스크린샷: "점프 고쳐줘" 요청에 대한 Claude의 응답 -->

결과를 보면서 다음을 확인해 봅니다.

* Claude가 **무엇이 문제라고 판단했는지** (공중 점프? 점프 높이? 입력 감도?)
* **요청하지 않은 것**까지 바꾸지는 않았는지
* 이동 방식(`transform.Translate`) 문제도 발견했는지

운이 좋으면 잘 고쳐주기도 하지만, 매번 결과가 달라집니다. "점프가 문제"라는 정보만으로는 어떤 증상인지 알 수 없기 때문입니다.

### 되돌리기 - `/rewind`

다음 실습을 위해 코드를 원래대로 돌려놓겠습니다. Claude Code는 파일을 고칠 때마다 체크포인트를 남겨두기 때문에, git이 없어도 되돌릴 수 있습니다.

```
/rewind
```

또는 입력창에서 `Esc`를 두 번 누르면 됩니다. 되돌릴 시점을 고르고, **코드만 되돌릴지, 대화까지 되돌릴지** 선택할 수 있습니다. 여기서는 코드와 대화를 모두 되돌려 줍니다.

<!-- 📷 스크린샷: /rewind 선택 화면 -->

> 체크포인트는 Claude가 직접 고친 파일만 추적합니다. 유니티 에디터에서 직접 바꾼 내용이나, 터미널 명령으로 바뀐 파일은 되돌리지 못하니 중요한 작업 전에는 git 커밋을 함께 해두는 것이 안전합니다.

## 4. 실습 2 - Plan mode로 제대로 시켜보기

### Plan mode란?

Plan mode에서는 Claude가 **파일을 읽기만 하고 수정하지 않습니다.** 코드를 살펴보고 계획을 세운 뒤, 사용자가 승인해야 실제 작업을 시작합니다.

* CLI(터미널)에서는 `Shift + Tab`을 누를 때마다 모드가 바뀝니다. 화면 아래에 `plan mode on`이 표시되면 됩니다.
* Desktop 앱에서는 입력창 아래의 모드 선택 메뉴에서 Plan을 고릅니다.

<!-- 📷 스크린샷: Plan mode가 켜진 상태의 입력창 -->

### 구체적으로 요청하기

Plan mode를 켠 상태에서 아래처럼 요청합니다.

```
@Assets/Scripts/PlayerController.cs 를 읽고 문제점을 찾아줘.
증상: 스페이스바를 연타하면 공중에서도 계속 점프됨.
그리고 Rigidbody가 있는데 이동 방식이 맞는지도 봐줘.
고치기 전에 계획만 먼저 보여줘.
```

앞의 요청과 비교하면 다음이 달라졌습니다.

* **`@파일명`으로 파일을 직접 가리켰습니다.** `@`를 입력하면 파일 자동완성이 뜹니다. Claude가 파일을 찾아 헤맬 필요가 없습니다.
* **증상을 구체적으로 적었습니다.** "점프가 이상해"가 아니라 "연타하면 공중에서도 점프됨"이라고 썼습니다.
* **추가로 볼 부분을 알려줬습니다.** 이동 방식도 확인해 달라고 범위를 정해줬습니다.
* **계획부터 보여달라고 했습니다.**

<!-- 📷 스크린샷: Claude가 제시한 수정 계획 -->

계획이 나오면 꼼꼼히 읽어보고, 마음에 들지 않는 부분이 있으면 수정을 요청합니다. 예를 들어 땅 체크를 Raycast로 하겠다고 했는데 충돌 이벤트(`OnCollisionEnter`) 방식이 더 좋다면, 그렇게 말해주면 됩니다. 계획이 괜찮다면 승인합니다.

### 수정 결과 확인

보통 다음과 같은 방향으로 수정됩니다. (Claude의 응답은 매번 조금씩 다를 수 있습니다.)

* 땅에 닿아 있는지 확인하는 코드 추가 (`Physics.Raycast` 또는 충돌 체크)
* 이동을 `FixedUpdate`로 옮기고, `rb.linearVelocity` 또는 `rb.MovePosition`으로 변경
* 입력은 `Update`에서 받고, 물리 처리는 `FixedUpdate`에서 하도록 분리

> Unity 6부터는 `Rigidbody.velocity`가 `Rigidbody.linearVelocity`로 이름이 바뀌었습니다. Claude가 `velocity`를 쓰면 경고가 뜨니, 그때는 바꿔달라고 하면 됩니다.

## 5. 실습 3 - 검증까지 시키기

코드를 고쳤다면 끝이 아닙니다. 제대로 고쳐졌는지 확인하는 방법까지 물어봅니다.

```
수정한 코드가 왜 이 문제를 해결하는지 설명하고,
Play 모드에서 내가 확인해야 할 테스트 항목을 3개 알려줘.
```

<!-- 📷 스크린샷: 테스트 항목 3개 -->

알려준 항목대로 Play 모드에서 직접 확인해 봅니다.

* 땅에서 스페이스바를 누르면 점프가 되는지
* 공중에서 스페이스바를 연타해도 추가 점프가 안 되는지
* 벽(Cube 하나 세워서)에 부딪혔을 때 뚫고 지나가지 않는지

이 과정을 통해 Claude가 고친 코드를 **내가 이해하고 있는지**도 함께 확인할 수 있습니다. 이해하지 못한 코드를 그대로 쓰면, 나중에 문제가 생겼을 때 고칠 수가 없습니다.

## 6. 좋은 프롬프트를 쓰는 요령

실습에서 쓴 방법을 정리하면 다음과 같습니다.

| 요령 | 나쁜 예 | 좋은 예 |
|---|---|---|
| 증상을 구체적으로 | 점프 고쳐줘 | 연타하면 공중에서도 계속 점프됨 |
| 파일을 직접 가리키기 | 플레이어 스크립트 봐줘 | `@Assets/Scripts/PlayerController.cs` |
| 범위 정해주기 | 알아서 고쳐줘 | 점프랑 이동 방식만 봐줘 |
| 계획 먼저 | (바로 구현) | 고치기 전에 계획만 보여줘 |
| 검증 기준 | (없음) | Play 모드에서 확인할 항목 알려줘 |

이외에도 다음 방법이 유용합니다.

* **스크린샷 붙여넣기**: 콘솔 에러나 UI가 깨진 화면을 캡처해서 입력창에 붙여넣거나 드래그하면 Claude가 이미지를 보고 판단합니다.
* **에러 메시지 그대로 붙여넣기**: 콘솔 에러를 요약하지 말고 스택 트레이스까지 통째로 붙여넣습니다.
* **도중에 멈추기**: Claude가 이상한 방향으로 가고 있다면 `Esc`를 눌러 바로 멈추고 방향을 다시 잡아줍니다.

## 7. 권한 모드

Claude Code는 파일을 수정하거나 명령을 실행하기 전에 허락을 구합니다. 이 동작은 권한 모드로 조절할 수 있습니다.

| 모드 | 동작 |
|---|---|
| 기본 (default) | 파일 수정, 명령 실행마다 허락을 구함 |
| 편집 자동 허용 (acceptEdits) | 파일 수정은 묻지 않고, 명령 실행만 허락을 구함 |
| Plan | 읽기만 하고 수정하지 않음 |
| Auto | 대부분의 작업을 알아서 진행하고, 위험해 보이는 작업만 확인 |

`Shift + Tab`(CLI) 또는 입력창의 모드 메뉴(Desktop 앱)로 바꿀 수 있습니다.

처음에는 **기본 모드**로 Claude가 어떤 파일을 고치고 어떤 명령을 실행하는지 하나하나 지켜보는 것을 추천합니다. 익숙해지고 나서 편집 자동 허용이나 Auto 모드로 넘어가면 됩니다.

허락을 구하는 창에서 "이 명령은 앞으로 묻지 않기"를 선택하면, 해당 명령은 `.claude/settings.local.json`의 허용 목록에 추가되어 다음부터는 묻지 않습니다.

## 마치며

같은 버그라도 어떻게 요청하느냐에 따라 결과가 크게 달라졌습니다. 핵심은 세 가지입니다.

* **구체적으로** 요청하기 (증상, 파일, 범위)
* 큰 작업은 **계획부터** 받아보기
* 결과를 **어떻게 확인할지**까지 물어보기

하지만 매번 "우리 프로젝트는 Unity 6이고, 새 Input System을 쓰고, 물리는 FixedUpdate에서..."라고 설명하는 건 번거롭습니다. 다음 글에서는 이런 프로젝트 정보를 한 번만 적어두면 Claude가 매번 알아서 읽어가는 **CLAUDE.md**를 다뤄보겠습니다.
